# 0004: separate durable intake, check results and publication

Accepted for local engineering. This adds a real held-file boundary and a bounded CSV contract engine. It does not qualify malware scanning, cryptographic verification, complete processing workflows or a full customer journey.

A saved parcel is not an approved parcel. Newly accepted bytes under a partner intake policy have an immutable `intake-csv-v1:POLICY_HASH` tag. Their file/check/receipt records commit after filesystem sync, while their requested namespace path stays absent. A parser pass is another durable fact; it still grants no read or delivery authority. Exact release approval separately commits a minimal release proof and publication with the receipt.

Policy definitions and file bindings are immutable event projections. Runtime cannot update accepted file bytes or mutate a check's file, policy, storage UUID, target, parent or authority snapshot. All four new tables enforce forced tenant/partner row security; check bindings and command receipts also enforce actor restriction. Minimal shared release proofs let normally authorized partner readers use approved paths without exposing private check bindings.

Application read/worker checks and SQL publication/delivery guards both consult the release gate. A deferred constraint rejects a new controlled file without its bound held check and rejects new unchecked acceptance after policy configuration. Existing integrity-only revisions keep their explicit historical scope; the new policy does not fabricate retroactive verdicts. Replays keep the original operation, not the meaning of a later policy.

Two PostgreSQL session slots admit deterministic checks separately from delivery and inference. A durable worker identity, attempt and 70-second database lease precede parsing; final writes recheck that identity and revision. A fresh key may replace an expired attempt; an old worker cannot write over the replacement. The CSV engine receives a bounded reader and typed policy, bounds input/record/field/row/time use, and retains only codes, counters and immutable references. It has no endpoint or process interface. A native process-pause experiment exercises the actual lease and stale-owner boundary.

Policy rotation/revocation fails current checks and prevents further controlled-file reads or dispatch. Both HTTP ranges and SFTP reads recheck current authority and release before bounded descriptor reads. Already received bytes cannot be recalled. The current owner-bound service does not yet rebind old held revisions, delegate review to another actor, run unattended checks, re-scan a released file or implement protected retention/cleanup. Those are explicit remaining work, alongside other validators, antivirus/ICAP/DLP engines, signature workflows and complete production resource qualification.
