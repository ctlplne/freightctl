# Initial trust boundaries and attacks

This is a living design record, not a completed security assessment.

| Boundary | What can go wrong | Required control and proof |
| --- | --- | --- |
| Client to protocol/API | Wrong identity, replay, oversized body, slow request | TLS/SSH verification, short scoped credentials, idempotency, size/time/concurrency admission; stock-client rejection tests |
| Identity to tenant/partner | Token chooses somebody else's scope | Authenticate identity first; service authorization plus forced SQL row policies; direct non-owner SQL and API isolation tests |
| Service to PostgreSQL | Missing journal, leaked pooled scope, altered events | Local transaction scope, tenant-aware keys, atomic journal/index/idempotency, least grants; rollback/concurrency/permission tests |
| Service to storage | Partial bytes, path escape, links, replacement, disk full | Private root, generated identities, descriptor-relative confinement, sync before acceptance, exact digest; real filesystem and crash tests |
| Processing to publication | Scanner offline called clean, archive bomb, changed bytes | Immutable revisions, pinned check identity, bounded separate workers, quarantine and current approvals; independent scanner/parser tests |
| Local scanner to verdict | Forged/early clean reply, database drift, stale proof, unsafe engine settings | Private protected Unix socket/configuration, correlated before/after versions, exact source hash/length, expiring proof, immutable enrollment and SQL publication gate; protocol adversaries and real outage controls tested, genuine engine/corpus and OS resource qualification remain open |
| Partner key to signed-file release | Same-name attacker key, substituted signature, weak hash, revoked signer | Independently confirmed full fingerprint, immutable version/hash, bounded public-only packets, exact source/signature proof and current revocation/expiry gate; independent GnuPG and real PostgreSQL rejection tests |
| Approved source/recipient to encrypted delivery | Wrong recipient, plaintext fallback, changed retry ciphertext, orphan publication | Purpose-bound public recipient/subkey, exact workflow/destination approval, bounded separate generation, immutable ciphertext acceptance before connection, live fencing/revocation and exact ciphertext receipts; stock GnuPG/SFTP plus process-death and failed-receipt tests |
| Delivery to peer | Changed host identity, forged receipt, double payment | Approved endpoint/trust, durable intent, fencing, receiver receipt contract; independent receiver and crash-after-send tests |
| Browser to action | CSRF, XSS, stolen invitations, inaccessible recovery | Origin/session controls, safe rendering, expiry/recall, WCAG journeys; real browser tests |
| Untrusted data to AI/tool | Prompt injection, invented recipient, private disclosure | Redact authorized context, structured proposal validation, revision-bound approvals, no ambient execution rights; adversarial cases |
| Worker/agent to host/network | Arbitrary shell, SSRF, runaway processing | Explicit capabilities, no imported script execution, isolated pools, approved network targets and budgets; denial tests |
| Operations to retained data | Lost key, inconsistent restore, unsafe upgrade | Key references and custody, consistent backup manifest, clean restore and reconciliation; AI-disabled/offline recovery |
| Build to distribution | Leaked secrets, vulnerable dependencies, fake qualification | Pinned dependencies, scans with feed/input manifests, signed reproducible builds, honest red gates; owner authority before publication |

Host root, storage administrators and PostgreSQL superusers can defeat local controls. Protection against them needs independent retention, key custody and tamper-evident exports; no claim is made yet. A single local disk does not survive disk loss. Payload content and ordinary filenames must stay out of default logs. Public test data is synthetic; credentials and raw evidence stay in ignored `.private/` and `evidence/raw/`.

[Held intake](0004-held-intake.md) now implements a concrete processing/publication boundary for new revisions under an explicit CSV policy. Raw IDs and administrator mode bypass cannot release held bytes; exact operator release, current policy and byte re-verification are required. HTTP/SFTP reads and delivery workers recheck the gate. Actor-private reports contain no offending cell values. The real delayed-worker test retains the production lease and refuses stale ownership. These controls do not establish antivirus coverage, retrospective policy enforcement, delegated review, protected retention or a complete secure-business-file journey.

[Detached signature intake](0005-openpgp-intake.md) adds public-key enrollment under an explicit full fingerprint, immutable sidecar/source/policy binding and active-signer checks on release and availability. The same UID under a different key grants no trust. Unsupported packet types, private keys, mixed blocks, weak message hashes and oversized inputs are rejected before verification. The library never fetches keys or launches a process. Resource-bounded synthetic GnuPG evidence covers selected v4 peer profiles; cryptographic algorithm/platform coverage, private signing/decryption custody and production resource qualification remain open. Journals contain bounded public key configuration and signature references, never secret keys or raw file/signature payloads.

Check-worker recovery treats status as information, not permission. An untrusted client can change displayed time or submit another reservation, but conditional replacement still requires the authenticated actor's private check, current read/check_run authority, unchanged immutable source/storage/namespace/policy binding, exact revision/worker/expiry selectors and an expired PostgreSQL lease under the claim row lock. Timestamp selectors preserve exact microseconds across offsets. Durable replacement retains the original fenced worker/attempt rules, two-slot pool and attempt cap; it cannot reset quotas or publish bytes. A stale review is refused, and an unconfirmed response reuses the same operation identity. Native SIGKILL/lease/browser evidence supplements the existing paused-late-worker and SQL isolation/publication gates. Multi-host restore and governed re-scan/rebind remain unqualified.
