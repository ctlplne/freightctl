# 0002: a virtual name points to a retained file revision

Accepted for local development, 2026-10-28. This checkpoint establishes namespace rules; full protocol and customer journeys remain open.

A folder is a PostgreSQL record. A file entry points to a sealed custody revision by ID. Think of the namespace as a card catalog: moving a card changes where a reader finds a file, while the original bytes remain in the vault. New contents create a new file ID and publication event. Never edit a sealed object or turn a user name into a host path.

Each account has explicit grants, a mounted root and an authority revision. The same service enforces them for CLI and HTTPS, and later protocol adapters. Transport middleware supplies proof of identity; request bodies cannot supply authenticated actor context. Token queries include explicit tenant and partner predicates as well as forced row policies. SSH may supply actor/key selectors only after the cryptographic transport verifies possession of the registered private key. Public keys in imported documents never grant authority by themselves.

All ten domain relations have forced tenant/partner policies. Each scoped transaction locks them and checks the policies before authentication. Per-actor upload/namespace receipt policies prevent another partner actor from reusing a key to obtain somebody else's result. Historical migration checkpoints retain their original actor binding.

The partner namespace lock serializes parent checks, revision checks, tree changes and publication. Namespace events, changed entries, immutable publication history and command receipts commit together. SQL guards bind exact projected values to their events. A mode, owner, path or revision change without the matching event fails. Tombstones retain identities and history. No deletion of bytes follows from a virtual remove.

Checks distinguish operation grants, current mode bits, mount boundaries and revision preconditions. A file ID alone grants nothing. Current publication entries determine non-admin access to archived revisions, including after a rename. Root admins can inspect retained bytes for recovery. Global audit/reconciliation views currently require root `/`, even when a mounted identity has those grants; scoped views need separate implementation.

AcceptAt validates the complete virtual destination before staging. Bytes are synced first, then acceptance and namespace publication commit in one transaction. A failed publication can retain a sealed orphan; it never returns successful publication. The existing single-storage admission lock and capacity accounting remain the initial profile. Scalable reservations, tenant fairness and interrupted-upload resume are still open.

Names use NFC, case-sensitive comparison and explicit byte/component limits. Validate the combined mount and requested name, not just each half: two permitted strings can form an overlong path. Canonical names cannot contain traversal, drive syntax or unsafe portable components. A rename is bounded to 1,000 entries and a command to ten seconds. Listing uses bounded keyset pages rather than reading an entire tree into memory.

Direct SSH cryptography stays in `internal/crypto`, using pinned `golang.org/x/crypto/ssh`. Supported-library algorithms exclude the library's insecure algorithm list; initial host identities are Ed25519, public identities allow Ed25519, P-256 and RSA 3072–8192. Certificate-based identities and FIPS qualification are not established. Parsed signer objects are library-owned Go objects and cannot be promised fully zeroized. The PostgreSQL `sha256(bytea)` call in migration 4 is an explicit database metadata-hash boundary used to bind public key wire bytes to events; it does not handle secret material. No secret values belong in events.

The SSH boundary admits one SFTP subsystem per connection and no shell, exec, environment, forwarding or agent channels. Idle activity refreshes the idle deadline without extending the absolute session deadline. Shutdown cancels and joins subsystem cleanup. Tests of this boundary use a synthetic subsystem. File-operation handlers, bounded packet/handle processing, write-close/disconnect semantics, key lifecycle commands and stock-client qualification must exist before claiming SFTP support.

Dependencies retain their upstream licenses: x/crypto, x/text, x/sys and x/sync are BSD-3-Clause Go subrepositories; pgx and its connection/pool dependencies retain their MIT licenses in the module cache. A distributable attribution inventory and license bundle remain required before release. Fetching or locally testing a dependency does not authorize distribution.

The native vulnerability scan reports GO-2026-5932 at module level because x/crypto also contains unmaintained OpenPGP packages. Those affected packages are absent from the native dependency graph; the scan reports no imported-package or reachable-symbol finding. Keep the original report and dependency inventory. The architecture gate forbids importing x/crypto/openpgp; future file-signature work needs a maintained implementation and fresh assessment. This is a reachability assessment, not removal of the advisory or release qualification. See the [official advisory](https://pkg.go.dev/vuln/GO-2026-5932).
