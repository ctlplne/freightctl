# 0005: bind detached signature proof to held source and explicit signer

Accepted for local engineering. A signature is a proof about an immutable revision, not a flag an uploader may set. The partner administrator enrolls public packets under an independently confirmed full primary fingerprint. Immutable intake policy selects the key version/hash. The actor-owned signature attachment binds source digest, storage UUID and policy, and syncs its separate bytes before journaling acceptance.

Use the maintained ProtonMail `openpgp/v2` library behind `internal/crypto`. The application framing guard rejects unsupported packet classes and bounds allocation before the library interprets them. There is no production GnuPG subprocess, key server, private-key import or trust based on user IDs. Public key packets are bounded public configuration in PostgreSQL; detached signature bytes are filesystem artifacts with journal references. RSA and curve operations remain in pinned libraries.

A CSV pass plus signature proof still leaves bytes held. Release re-verifies source/signature and current key, policy and actor authority against the exact approved report. SQL projection/release guards require the bound attachment and active unexpired signer. The minimal shared release proof carries key identity, signature hash and effective expiry, so authorized readers need no access to private check bindings. Revocation and proof expiry stop future bounded reads and dispatch; already received bytes are beyond recall.

New immutable key versions allow explicit overlap without changing old policies. Revocation is separate and terminal. This preserves reviewable identity choices and prevents an administrator rotation from silently blessing a failed file with a different signer. A replaced/rejected attachment requires a new revision; governed rebind, delegated approval, re-scan and retention remain open.

The existing check slot/attempt/lease budgets also bound signature work. The independent fixture uses GnuPG 2.4.9 with synthetic Ed25519 subkey and RSA3072/SHA256 artifacts, capped at 128 MiB/one CPU with network disabled. V6 unit coverage does not imply a v6 peer result. Encryption, decryption, private signing, malware scanning, wider protocols/peers, native Linux/Windows and complete business receipt remain mandatory. Details and operator commands are in [the OpenPGP profile](../openpgp.md).
