# Durable onboarding connectivity probes

Migration 20 adds `onboarding_probes`, the 42nd forced-RLS domain relation. No ordinary permission or elevated projection role is added. Current root `admin`, `accounts_manage` and `connections_manage` authority is required. Probe history belongs to its actor even though contact drafts can be shared by authorized partner managers.

The immutable definition binds the latest onboarding plan/version/hash, one outbound SFTP requirement, an actor-owned registered connection/version/hash, current credential authority and the `sftp-readonly-v1` profile. The service checks typed canonical configuration and path safety. API/model input cannot supply a host, key path, arbitrary protocol task or observed success. Changes create new reviewed work; old receipts do not restore authority.

The existing partner account-management lock precedes credential/session locks. Intent creation serializes admission and commits its source event, projection and start receipt together. Short connection row locks protect the reviewed version. Two independent PostgreSQL probe slots bound cross-process contact; transfer/scan slots remain separate. A queued probe receives one immutable work key and one owner with a 20-second database lease. Its claim commits before contact. The existing bounded SFTP transport supplies pinned host authentication and packet admission; the probe reads advertised extensions and traverses directory components without touching payloads.

Network I/O has a five-second deadline. The session-slot watchdog cancels contact if its PostgreSQL session disappears. Finalization opens a fresh scoped transaction and requires the same owner, work key, revision, definition and unexpired database lease. Current plan/connection/authority are rechecked and the connection locked before a positive result. SQL requires the exact transition event, field/flag consistency, reviewed current bindings and immutable definition/terminal state. Late workers cannot overwrite expiry or another result.

The probe never automatically contacts a receiver twice. Repeating the original work key returns a live/terminal record; expiry records an expired result without restarting. Completed/live/expired recovery requires no network-worker slot. History and status let an authorized operator recover after reload. Current binding status is distinct from historical outcome, and response types explicitly carry connectivity-only strength and false file-exchange/activation flags.

The native failure exposed a serialization boundary: PostgreSQL timestamp reload retained the instant but changed the textual timezone. Probe reads now normalize all timestamps to UTC, and real PostgreSQL/native tests compare exact serialized receipt fields. Another retained failure showed completed result recovery incorrectly competed for worker capacity; its saturation regression now passes without increasing the pool.

Actual SSH/extension/directory observations are weaker than file or business receipts. Full J05 still requires tested account/folder/workflow bindings, an independent exchange tied to the reviewed requirement, exact approval, activation and queued-work credential lifecycle. Other protocol/role profiles remain unimplemented or unqualified. Resource authorization for a genuine scanner is separate and grants no inference permission.
