# 0006: freeze ciphertext before an approved external effect

Accepted for local engineering. A recipient-encrypted delivery extends the existing typed `sftp.deliver` step. Approval binds connection/destination, filename and exact public recipient version/profile together; run creation freezes the source revision. This preserves one reviewable security meaning across CLI, HTTPS, imports and proposal validation.

Use the existing maintained OpenPGP backend behind `internal/crypto`, with explicit AES256/MDC-v1 and AES256/OCB-v2 profiles and no fallback. Enrollment verifies a public-only key, full primary fingerprint, selected encryption subkey, features and current expiry. Purpose is explicit; old verification registrations retain their original canonical hashes. All private recipient operations occur outside this application profile.

Randomized encryption cannot be regenerated safely on each external retry: a receiver would see different hashes for the same intent. Persist one immutable ciphertext artifact with exact source, policy, storage and recipient proof before any receiver connection. Commit its event/projection under the current delivery owner/fence. A later owner reuses its actual verified bytes. Sealed bytes without a committed projection remain visible orphans and cannot enter publication. No payload is stored in PostgreSQL.

Two separate encryption session slots admit local generation; they are released before transfer admission. A task-scoped PostgreSQL custody reservation serializes quota accounting with ordinary acceptance without holding delivery or key rows across cryptography. Short transactions and bounded source reads recheck current authority/recipient and fencing. Process death releases session locks. A delayed old owner cannot accept an artifact after replacement.

SQL exact-event guards and immutable projections bind artifact, source, worker, key/profile and definition hash. Deferred workflow/publication checks require the approved step's encryption and exact durable ciphertext receipt. Runtime remains a non-owner role without BYPASSRLS. Ciphertext has no ordinary file identity or namespace publication; run status and authorized reconciliation expose only metadata.

External SFTP publication retains the existing conservative intent/lease/ambiguity model. Receipt failure after remote success preserves the same artifact and requires read-only observation. It does not grant receiver business acceptance. Current key/workflow/connection revocation stops future effects; trust changes never silently rebind a queued job. Governing recovery after revocation, private signing/decryption, scans, transformations, UI, distributed storage and complete journeys remain required. See [operator details and evidence limits](../encrypted-delivery.md).
