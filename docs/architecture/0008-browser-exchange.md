# 0008: browser exchange uses the ordinary custody and approval engine

Accepted for local engineering. The React/TypeScript client calls the same scoped HTTPS operations as CLI and stock clients. It cannot create an account, choose host paths, bypass a held file, change an upload destination, or turn a model answer into approval. First-admin enrollment and identity-provider onboarding remain separate required work.

Serve reviewed client assets from the Go binary with exact source/output hashes. Admit only the named embedded assets. Use a strict Content Security Policy with same-origin scripts, styles, workers and connections, no inline/evaluated scripts, no frames and no form navigation. Uploaded bytes retain attachment/octet-stream handling and never become client application code. Build and type checks include the actual shipped assets.

An enrolled bearer credential opens a short-lived browser session. Standard HMAC-SHA256 behind `internal/crypto` derives a purpose-separated opaque token from the credential, tenant, partner and operation key. Identical login replay derives the same token and original expiry without storing plaintext credentials in PostgreSQL or requiring a shared server signing key. Another purpose derives the CSRF token. SQL stores only secret references/hashes and immutable authority/expiry, with journal and forced tenant/partner/actor row security.

The HttpOnly, Secure, SameSite=Strict host cookie carries the session credential. Cookie-authenticated changes also require the derived CSRF header and exact HTTPS origin. Explicit bearer authentication never falls back to another cookie identity. Every ordinary service transaction rechecks parent credential/hash, authority revision and live session state/expiry; long readers do the same before their next bounded read. Access or credential changes require a new login. Cookie clearing cannot retract bytes already delivered.

Logout is a close-only capability. A verified expired or revoked cookie can finish/replay its own logout; it cannot regain file authority. Keep this lookup private to the revocation operation. Commit revocation, its immutable events and the operation-meaning receipt in one transaction. An existing key cannot revoke a different session. Rollback must preserve the original live state when required receipt persistence fails. Distinct command receipts and active sessions have separate operational admission bounds.

Browser file hashing reads one 1 MiB slice at a time in a worker, using the pinned library in `web/src/crypto.ts`. Resume reselects and hashes the complete source, compares its size/digest to the owned ticket, reads the authoritative committed offset and sends only the suffix. Each chunk has a stable offset-bound key and digest. Pause cancels a request; an uncertain request may already have committed. Resume therefore observes server progress rather than guessing. Separate pause/submit DOM identities prevent a cancel click from acquiring a submit default action during a render.

Downloads use native browser streaming and the same current file/release gate; the client does not assemble a whole-file JavaScript Blob. Before-stream refusals retain JSON for API clients and provide a readable refusal page for browser navigation. Required checks keep the file held. Human release displays and binds exact source, policy, report and revision; it is a separate action after passing checks.

Migrations 14 and 15 append two journal-backed relations; all thirty-three domain relations require non-owner forced row security. Existing grants and applied migrations are preserved. No model or scanner database is loaded by this client or its qualification. Native macOS Chromium automation remains an assisted narrow exchange exercise, not complete onboarding, independent adoption, full browser/WCAG coverage or production qualification.
