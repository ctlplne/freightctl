# Tenant directory and partner enrollment

Tenant-wide enrollment is a separate capability from a partner’s file/account grants. Migration 18 adds `tenant_administrators`, immutable `tenant_admin_commands` and immutable `partner_registrations`, bringing the forced-RLS domain relation count to 39. The 21 ordinary permissions and all existing grants remain unchanged. A version-1 first-run plan can explicitly opt in through an optional `tenant_administration` field; omitting it preserves the original canonical request and retry meaning.

Deployment maintenance grants/revokes a selected root administrator against exact membership and credential authority revisions. The current projection requires its immutable event; command receipts must match that event and projection. The serving role has SELECT-only authority-table access. A shared tenant advisory lock serializes these maintenance changes with enrollment before credential/session checks. PostgreSQL requires UPDATE privilege for row locking: the runtime keeps authority tables read-only, and the isolated projection role receives credential UPDATE only to take its controlling credential’s `FOR SHARE` lock. Its function issues no credential UPDATE.

Ordinary enrollment authenticates through the usual scoped runtime, checks root/admin/accounts authority and the separate current membership, and binds new execution to the reviewed credential and tenant-grant revisions. The manager’s requested first-admin grants must be a subset of its current grants. An exact prior receipt is available only after current authority checks; replay cannot create a new partner or restore a revoked grant.

The runtime inserts a registration with an exact source-partner `PartnerRegistered` event and original result. A narrow SECURITY DEFINER trigger, owned by the isolated NOLOGIN/non-owner/non-BYPASSRLS `freightctl_partners_writer` role, validates the context, event, result, fields, grants and both reviewed revisions. Its search path is pinned and row security stays on. Only then does it temporarily select the new partner/admin context, insert the partner and credential, and append the target-partner enrollment event. It restores the controlling context before returning. Deferred references bind the registration to the new administrator and its event. Any later error rolls back both scopes and the receipt.

The runtime gains no direct partner/credential write grants or writer-role membership. Every scoped transaction checks both projection roles’ ownership, non-elevated/non-login flags, lack of memberships/table ownership and pinned execution settings. Ordinary partner/file tables keep their original partner scope. A separately authorized tenant directory read policy exposes partner IDs and initial enrollment metadata; it does not expose another partner’s credentials, files, paths, workflows or transfer history.

Browser review freezes the complete enrollment decision and one operation key. The credential is generated locally, downloaded before commit, hashed through the existing browser crypto boundary and cleared from its controlled buffer on completion/cancel/unmount. Lost responses retry the same command. Definitive refusals block retry until a fresh review. A successful receipt clears earlier uncertainty messages and exports only versioned workspace IDs. Imported workspace data cannot choose an origin, credential, permission or command.

Current work covers partner enrollment and tenant authority lifecycle. Contacts, requirements/checklists, invitations/providers, broader delegation, environment separation/promotion, partner suspension, queued-work handling during lifecycle changes and full onboarding/production activation remain required. The native exercise is assisted same-host evidence; no model, real scanner engine or private crypto operation is used by it.
