# GitHub CI contract

The automatic [core workflow](../../.github/workflows/core-checks.yml) runs on pushes to `main` and pull requests. GitHub-hosted `ubuntu-24.04` is the native Linux x86_64 target; `ubuntu-24.04-arm` is native Linux arm64. Each native Go job checks `uname`, uses its own runner, starts a task-owned 512 MiB/one-CPU PostgreSQL container, builds the pinned offline GnuPG peer, and runs module verification, vet, unit/race and the full implemented PostgreSQL integration/migration suite. Cross-compilation and emulation do not count as native runtime checks.

The x86_64 source/browser job checks Go formatting, workflow syntax, qualification-ledger refusal and baseline mappings, exact JavaScript dependencies, frontend contracts, TypeScript, reproducible browser assets, dependency audit, reachable Go vulnerabilities and committed-source/full-history secrets. The x86_64 fuzz job runs the eight existing bounded parser/authority targets. A separate x86_64 stock-peer job uses real loopback PostgreSQL, OpenSSH SFTP source/receiver fixtures and a sandboxed browser to replay collection, arrival and schedule journeys. Run 11 passed these scripts with runner-installed Chrome 156.0.8078.47; Ubuntu AppArmor had rejected a sandbox for Playwright's downloaded Chromium shell. These are stand-in peers, not third-party production services.

Stock-peer work is split into isolated `arrivals-schedules` and `routing` matrix jobs. Routing runs the existing complete `qualify-routing.py` script against two independent stock SFTP receiver identities and the sandboxed browser. Its first Linux run failed the browser route phase (D105); the cause remains unassigned pending safe source-location diagnostics. Each matrix job emits a bounded allowlist of manifest outcomes and hashes through `ci-qualification-summary.py`, including source/commit binding, command/HTTP mismatches, output closure and exact fixture-database cleanup. Seven refusal/privacy contracts and replay of retained real manifest schemas pass locally. Browser diagnostics verify each report hash and emit only known script filename/line/column plus error/contact counts. Raw manifests, commands, private names, URLs and error text are excluded from that summary.

A third `captured-routing` matrix entry adds `--captured-routing`. It creates a second approved revision after the browser batch is durably captured, swaps the existing north/south rule branches while keeping source and recipient catalog exact, and reviews every captured file against those changed plans. The browser exercise includes lost proposal-response reload/recovery, withdrawal, approval retry with the original key, revocation without fallback, explicit new consent, ordinary independent dispatch reviews and byte-exact stock retrieval. It asserts each run binds the new authorization and workflow revision while the original capture/job stays unchanged and the source receives no further contact. Its first native run correctly rejected a fixture request using `id` instead of `workflow_id` (D104). The repaired request and seven local summary refusal/privacy tests need the original native replay; corrected-revision qualification remains red.

The [complete foundation replay](../../.github/workflows/full-foundation.yml) is available only through owner-triggered `workflow_dispatch`. The owner previously deferred that aggregate; the automatic jobs do not invoke `scripts/qualify-foundation.py`. No job loads a model or a malware signature database. The real scanner stays under its separate 4 GiB/one-CPU owner allowance and is not part of this CI.

The [native platform workflow](../../.github/workflows/native-platforms.yml) adds actual Windows amd64 and macOS arm64 Go unit checks without using the owner's machine. Its [first GitHub run](https://github.com/ctlplne/freightctl/actions/runs/41496634781) passed macOS ARM module/vet/unit race checks and exposed Windows permission, directory-sync, browser-byte and scanner-contract failures (D103). It does not run PostgreSQL or stock clients on those operating systems, so those platform gates remain open.

Workflows pin checkout/setup action commit IDs, Go, Node, the JavaScript lock, source scanners and peer image inputs. The token has read-only contents access; checkout does not persist credentials. Pull requests use the `pull_request` event, not `pull_request_target`, and no job receives repository secrets. Public CI logs are not an evidence vault: generated fixtures and raw outputs remain in ignored runner paths, and the workflows do not upload artifacts, push commits, publish packages/images or deploy.

[Run 9](https://github.com/ctlplne/freightctl/actions/runs/41491331244) established actual native Linux outcomes: bounded fuzz passed; x86_64 and arm64 unit/race checks passed; stock SFTP collection and arrival scripts completed. Source checks stopped at ShellCheck, both integration jobs stopped at protected GnuPG fixture access, and the schedule browser produced no report. [Run 10](https://github.com/ctlplne/freightctl/actions/runs/41494054412) passed the complete source/security and fuzz jobs. Both native integration jobs advanced past the first GnuPG fixture failure, then failed at a second protected recipient mount (D102). The early browser probe showed Ubuntu AppArmor denied Playwright's downloaded Chromium shell a usable sandbox (D101). The current workflows keep private mounts and browser sandboxing intact. A missing prerequisite fails its job; no assertion, isolation check or budget is relaxed. CI results supplement, but do not close, the 83 baseline rows, 12 full journeys, native production platforms, independent adoption, or release/enterprise gates.

[Run 11](https://github.com/ctlplne/freightctl/actions/runs/41496634777) passed all five core jobs, including both full native PostgreSQL integration/migration suites. Each verbose integration log has 519 passed case/subcase records, zero skips and zero failures. [F043](evidence/F043-native-ci.json) binds the result to commit `1ebf6d0`, identified runners and the observed limits. Windows remains a required red platform gate.

[The durable GitHub Actions plan](github-actions-plan.md) inventories the remaining work that can move to native runners, the real or stand-in peers each claim needs, and the external dependencies that GitHub cannot replace.
