# GitHub CI contract

The owner authorized public source and CI pushes for the existing `ctlplne/freightctl` repository. These workflows test the pushed commit after it arrives on local `main`; they are regression evidence, not a pre-push merge barrier. Every result stays bound to its actual commit, operating system, architecture and peer. A skipped, filtered, cancelled or queued job gives no runtime pass.

The automatic workflows separate the work:

- [Source and security](../../.github/workflows/core-checks.yml) checks formatting, actionlint/ShellCheck, qualification records and their refusal tests, frontend contracts, TypeScript, reproducible assets, npm audit, reachable Go vulnerabilities and committed-source/full-history secrets.
- [Native Linux](../../.github/workflows/native-linux.yml) checks `uname` on actual Ubuntu x86_64 and arm64 runners, then runs module verification, vet, unit race and all implemented real PostgreSQL integration/migration race tests. The race detector checks unsafe shared-memory access while the database tests exercise actual transactions and locks. Each runner owns a 512 MiB/one-CPU PostgreSQL container and the pinned offline GnuPG peer. A separate x86_64 job runs eight bounded parser/authority fuzz targets. Separate x86_64/ARM jobs prepare a real PostgreSQL custom dump/transactional restore of synthetic first-run metadata, with exact table/security comparison and protected raw outputs. Schema33/34 pass inF050/F052. The schema35 report on d2d389a remains red at D116; its shared-profile repair needs native replay.
- [Stock peers](../../.github/workflows/stock-peers.yml) runs isolated `arrivals-schedules`, `routing`, `captured-routing`, `intake-routing` and `handoff-routing` entries against real loopback PostgreSQL, stock OpenSSH source/receivers and sandboxed Chrome. Handoffs add the pinned offline GnuPG receiver proof. These are synthetic stand-in estates, not customer or licensed vendor environments.
- [Native platforms](../../.github/workflows/native-platforms.yml) runs Go module/vet/unit checks on actual Windows amd64 and Mac ARM, with race checks on Mac. PostgreSQL, Windows services, SFTP and agents on those platforms need separate qualification.
- [Full foundation](../../.github/workflows/full-foundation.yml) remains owner-triggered `workflow_dispatch` only. The owner deferred F026's final aggregate; automatic jobs do not invoke it.

Native Go/platform workflows select application, dependency and own-workflow changes plus manual dispatch. Linux also selects its PostgreSQL/GnuPG provisioning and metadata-restore utility/refusal inputs. Stock peers additionally select qualification scripts but exclude changes confined to Go `_test.go` files under `cmd/` and `internal/`, since those files are absent from the server build. Native Go tests still execute them. Application Go/SQL, browser/dependency, provisioning/qualification scripts and the stock workflow remain included. Manual dispatch can replay another candidate. A filtered stock job retains the last actual tested candidate; it does not become a new pass.

Action commit IDs, Go 1.26.10, Node 26.0.0, lockfiles, source scanners and peer image inputs are pinned. Job logs record actual tools and runner/peer versions. Ubuntu AppArmor refused Playwright's downloaded Chromium shell (D101); selecting installed Chrome preserves `chromiumSandbox:true` without disabling host isolation. Protected GnuPG mounts run as their fixture-owning uid/gid (D100/D102), with original permissions and resource limits intact.

Every workflow uses read-only contents access and checkout without persisted credentials. Pull requests use `pull_request`, receive no repository secrets and own fresh loopback fixtures. No workflow authors commits, uploads raw artifacts, publishes packages/images or deploys. No job starts inference or downloads weights. Real scanner work retains its separate 4 GiB/one-CPU allowance and is outside these jobs; scanner protocol fixtures and CSV checks start no engine.

Public logs are not an evidence vault. `ci-qualification-summary.py` checks exact commit/source binding, command/HTTP outcomes, unique output closure, original browser report hashes and exact database cleanup. It publishes only allowlisted states, hashes and counts, plus known browser source locations on failure. Seven privacy/refusal contracts protect that boundary. Commands, payloads, private names, URLs, credentials and raw errors stay in ignored runner paths; they are not uploaded. Runner files disappear, so safe checked-in records retain the result and its limits rather than claiming a complete downloadable raw bundle.
