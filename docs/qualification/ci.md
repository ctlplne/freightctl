# GitHub CI contract

The automatic [core workflow](../../.github/workflows/core-checks.yml) runs on pushes to `main` and pull requests. GitHub-hosted `ubuntu-24.04` is the native Linux x86_64 target; `ubuntu-24.04-arm` is native Linux arm64. Each native Go job checks `uname`, uses its own runner, starts a task-owned 512 MiB/one-CPU PostgreSQL container, builds the pinned offline GnuPG peer, and runs module verification, vet, unit/race and the full implemented PostgreSQL integration/migration suite. Cross-compilation and emulation do not count as native runtime checks.

The x86_64 source/browser job checks Go formatting, workflow syntax, qualification-ledger refusal and baseline mappings, exact JavaScript dependencies, frontend contracts, TypeScript, reproducible browser assets, dependency audit, reachable Go vulnerabilities and committed-source/full-history secrets. The x86_64 fuzz job runs the eight existing bounded parser/authority targets. A separate x86_64 stock-peer job uses real loopback PostgreSQL, OpenSSH SFTP source/receiver fixtures and a sandboxed browser to replay collection, arrival and schedule journeys. The next candidate selects the runner-installed Chrome channel because Ubuntu AppArmor rejected a sandbox for Playwright's downloaded Chromium shell. That candidate is pending a live run. These are stand-in peers, not third-party production services.

The [complete foundation replay](../../.github/workflows/full-foundation.yml) is available only through owner-triggered `workflow_dispatch`. The owner previously deferred that aggregate; the automatic jobs do not invoke `scripts/qualify-foundation.py`. No job loads a model or a malware signature database. The real scanner stays under its separate 4 GiB/one-CPU owner allowance and is not part of this CI.

The prepared [native platform workflow](../../.github/workflows/native-platforms.yml) adds actual Windows amd64 and macOS arm64 Go unit checks without using the owner's machine. Its first GitHub result is pending. It does not run PostgreSQL or stock clients on those operating systems, so those platform gates remain open.

Workflows pin checkout/setup action commit IDs, Go, Node, the JavaScript lock, source scanners and peer image inputs. The token has read-only contents access; checkout does not persist credentials. Pull requests use the `pull_request` event, not `pull_request_target`, and no job receives repository secrets. Public CI logs are not an evidence vault: generated fixtures and raw outputs remain in ignored runner paths, and the workflows do not upload artifacts, push commits, publish packages/images or deploy.

[Run 9](https://github.com/ctlplne/freightctl/actions/runs/41491331244) established actual native Linux outcomes: bounded fuzz passed; x86_64 and arm64 unit/race checks passed; stock SFTP collection and arrival scripts completed. Source checks stopped at ShellCheck, both integration jobs stopped at protected GnuPG fixture access, and the schedule browser produced no report. [Run 10](https://github.com/ctlplne/freightctl/actions/runs/41494054412) passed the complete source/security and fuzz jobs. Both native integration jobs advanced past the first GnuPG fixture failure, then failed at a second protected recipient mount (D102). The early browser probe showed Ubuntu AppArmor denied Playwright's downloaded Chromium shell a usable sandbox (D101). The next candidate keeps private mounts and browser sandboxing intact and needs a live replay. A missing prerequisite fails its job; no assertion, isolation check or budget is relaxed. CI results supplement, but do not close, the 83 baseline rows, 12 full journeys, native production platforms, independent adoption, or release/enterprise gates.

[The durable GitHub Actions plan](github-actions-plan.md) inventories the remaining work that can move to native runners, the real or stand-in peers each claim needs, and the external dependencies that GitHub cannot replace.
