# GitHub CI contract

The automatic [core workflow](../../.github/workflows/core-checks.yml) runs on pushes to `main` and pull requests. GitHub-hosted `ubuntu-24.04` is the native Linux x86_64 target; `ubuntu-24.04-arm` is native Linux arm64. Each native Go job checks `uname`, uses its own runner, starts a task-owned 512 MiB/one-CPU PostgreSQL container, builds the pinned offline GnuPG peer, and runs module verification, vet, unit/race and the full implemented PostgreSQL integration/migration suite. Cross-compilation and emulation do not count as native runtime checks.

The x86_64 source/browser job checks Go formatting, workflow syntax, qualification-ledger refusal and baseline mappings, exact JavaScript dependencies, frontend contracts, TypeScript, reproducible browser assets, dependency audit, reachable Go vulnerabilities and committed-source/full-history secrets. The x86_64 fuzz job runs the eight existing bounded parser/authority targets. A separate x86_64 stock-peer job uses real loopback PostgreSQL, OpenSSH SFTP source/receiver fixtures and Chromium to replay collection, arrival and schedule journeys. These are stand-in peers, not third-party production services.

The [complete foundation replay](../../.github/workflows/full-foundation.yml) is available only through owner-triggered `workflow_dispatch`. The owner previously deferred that aggregate; the automatic jobs do not invoke `scripts/qualify-foundation.py`. No job loads a model or a malware signature database. The real scanner stays under its separate 4 GiB/one-CPU owner allowance and is not part of this CI.

Workflows pin checkout/setup action commit IDs, Go, Node, the JavaScript lock, source scanners and peer image inputs. The token has read-only contents access; checkout does not persist credentials. Pull requests use the `pull_request` event, not `pull_request_target`, and no job receives repository secrets. Public CI logs are not an evidence vault: generated fixtures and raw outputs remain in ignored runner paths, and the workflows do not upload artifacts, push commits, publish packages/images or deploy.

The checked-in workflows and local actionlint result establish configuration only. Native x86_64/arm64 behavior, browser availability, package/image acquisition, stock-client journeys and GitHub job outcomes remain unverified until a real run on GitHub. A missing prerequisite fails its job; no assertion, isolation check or budget is relaxed. CI results supplement, but do not close, the 83 baseline rows, 12 full journeys, native production platforms, independent adoption, or release/enterprise gates.
