# GitHub CI contract

The owner authorized public source and CI pushes for the existing `ctlplne/freightctl` repository. These workflows test the pushed commit after it arrives on local `main`; they are regression evidence, not a pre-push merge barrier. Every result stays bound to its actual commit, operating system, architecture and peer. A skipped, filtered, cancelled or queued job gives no runtime pass.

Owner decision S004 makes product construction the priority. The [capacity audit](evidence/F084-ci-runner-capacity.json) removes arbitrary GitHub build/scanner ceilings and records actual sizes. GitHub helper Go/Node environments and Chrome arguments stop inheriting the laptop profile; local limits remain unchanged. Correctness, secrets, vulnerability findings, custody, isolation and exact evidence remain gates. Failed historical scans remain failed until actual repaired replay. The platform still has finite runner capacity and a job lifetime; it is not an unlimited machine.

The automatic workflows separate the work:

The race detector checks unsafe shared-memory access while the database tests exercise actual transactions and locks. Each runner owns a 512 MiB/one-CPU PostgreSQL container and the pinned offline GnuPG peer. A separate x86_64 job runs ten bounded parser/authority fuzz targets. Separate x86_64/ARM jobs prepare a real PostgreSQL custom dump/transactional restore of synthetic first-run metadata, with exact table/security comparison and protected raw outputs. Native Go/platform workflows select application, dependency and own-workflow changes plus manual dispatch. Linux also selects its PostgreSQL/GnuPG provisioning and metadata-restore utility/refusal inputs. Stock peers additionally select qualification scripts but exclude changes confined to Go `_test.go` files under `cmd/` and `internal/`, since those files are absent from the server build. Native Go tests still execute them. Application Go/SQL, browser/dependency, provisioning/qualification scripts and the stock workflow remain included. Manual dispatch can replay another candidate. A filtered stock job retains the last actual tested candidate; it does not become a new pass.

Action commit IDs, Go 1.27.3, Node 26.13.0, lockfiles, source scanners and peer image inputs are pinned. Job logs record actual tools and runner/peer versions. Ubuntu AppArmor refused Playwright's downloaded Chromium shell (D101); selecting installed Chrome preserves `chromiumSandbox:true` without disabling host isolation. Protected GnuPG mounts run as their fixture-owning uid/gid (D100/D102), with original permissions and resource limits intact.

Every workflow uses read-only contents access and checkout without persisted credentials. Pull requests use `pull_request`, receive no repository secrets and own fresh loopback fixtures. No workflow authors commits, uploads raw artifacts, publishes packages/images or deploys. No job starts inference or downloads weights. Real scanner work retains its separate 4 GiB/one-CPU allowance and is outside these jobs; scanner protocol fixtures and CSV checks start no engine.

Public logs are not an evidence vault. `ci-qualification-summary.py` checks exact commit/source binding, command/HTTP outcomes, unique output closure, original browser report hashes and exact database cleanup. It publishes only allowlisted states, hashes and counts, plus known browser source locations on failure. Seven privacy/refusal contracts protect that boundary. Commands, payloads, private names, URLs, credentials and raw errors stay in ignored runner paths; they are not uploaded. Runner files disappear, so safe checked-in records retain the result and its limits rather than claiming a complete downloadable raw bundle.
