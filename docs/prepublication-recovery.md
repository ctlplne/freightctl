# Recover queued work that stopped before publication

Choose **Failed before publication: verify the complete journal** in **Queued work after rotation** when an explicit production delivery has already tried to stage bytes. This is a separate profile, `prepublication-production-handoff-v1`. The default untouched profile still refuses every recorded attempt.

An attempted transfer may have a retained local ciphertext and a remote `.freightctl-DELIVERY_UUID-FENCE.partial`. That name is staging, not the final delivery. Downstream consumers must ignore these reserved partial names. A partner that processes partial files needs its own receiver reconciliation contract; this proof cannot establish whether its business system consumed them.

The sender commits its `publishing` transition before creating the final remote link. Recovery requires the complete immutable transition journal to prove that boundary was never crossed. A retry label, missing remote file, new credential or expired lease alone is insufficient. Every transition revision from 1 through the exact reviewed current revision must exist exactly once, carry the original immutable source/destination definition, and remain in draft, queued, staging, retry or blocked state. The server bounds this check to 256 transitions and hashes their actual event IDs and complete stored payloads. The 257th record, missing/duplicate revision, extra uncommitted-to-projection record, malformed record or any publication state refuses recovery. This is a processing bound, not a commercial limit.

The current delivery must have 1–8 attempts with its matching fence and be `retry`, `blocked`, or `staging` under its **original expired lease**. A live staging lease refuses preview, approval and execution. Worker slots, attempt limits, lease durations and security checks remain unchanged. The server never shortens a lease to obtain eligibility.

1. Inspect the exact original production run, immutable dispatch hash and recorded outcome. For publishing, ambiguous or succeeded work, reconcile that original outcome rather than using this path.
2. Complete the normal replacement connection/key enrollment, current connectivity probe, approved workflow, actual test exchange and approved active release. Preserve the saved plan, requirement, workflow family, receiver account/address/directory/filename, storage and encryption mode/profile. Bytes and length must remain identical.
3. Keep the original accepted file when current policy permits, or select its completed direct governed re-check child after fresh checks and separate release. An unlinked equal-byte upload cannot replace it.
4. Select the explicit pre-publication profile and preview. Review original state, run/delivery revisions, attempts/fence, complete history count/hash/last event, retained ciphertext identity/digest/length, both key/authority bindings and the exact target. No receiver contact occurs.
5. Save the private proposal, then separately approve the exact definition. Execution rechecks the same source proof under the original run/intent row locks. If a worker, cancellation, authority, key, policy or target change wins, execute refuses and the proposal needs a new review.
6. Execute the approved metadata handoff. Cancellation of the original, one new ordinary run/delivery intent, immutable handoff/production links, events and the original-key receipt commit together. A failed receipt or any other transaction failure rolls back both sides. The original attempt/fence, ciphertext, immutable dispatch and old receipts remain evidence. Its expired lease is cleared; stale workers cannot publish that cancelled intent.
7. Inspect the successor and execute its transfer separately. It gets a new delivery identity and fresh ciphertext for the approved current recipient. Verify the actual receipt and independently received bytes. Keep the original partial and ciphertext for governed disposition; this operation neither resends them nor deletes them.

The preview selector adds `"profile": "prepublication-production-handoff-v1"` to the ordinary [handoff selection](queued-production-handoffs.md). The returned definition adds `prepublication_proof: {transitions, history_hash, last_event_id, ciphertext}`; ciphertext is null if none was prepared, otherwise it names the immutable object ID, SHA-256 and byte length. This exact proof participates in the ordinary definition hash, proposal, separate approval and idempotent execution. Browser, CLI and API use the same service and permissions. Existing untouched definitions and hashes retain their original shape.

Migration 25 adds an indexed immutable transition lookup and the guarded eligibility/cancellation rules. It adds no domain tables or permissions; all 48 domain tables retain forced row security and the runtime remains a non-owner without bypass. The extra blocked/expired-staging cancellation transition is valid only with an atomic completed approved handoff and its exact source proof. Ordinary cancellation behavior is unchanged.
